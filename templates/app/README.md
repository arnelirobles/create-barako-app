## What is here

```
compose.yml        postgres, the API, the console. Pinned tags, not latest.
seed/seed.mjs      applies the {{BLUEPRINT}} blueprint, publishes a few entries
lib/cms.ts         the read path: public delivery, no auth
lib/session.ts     the write path: sign in on the server, cookie to the browser
app/               the site
```

## The three things worth knowing

**Content is data, not code.** Content types are defined at runtime. Adding a field to `post` is a
change in the console, not a migration and not a deploy. The one place this project depends on a
field name is `lib/cms.ts`, which maps a stored entry onto the shape the pages render.

**Delivery is opt in, twice.** A page only sees an entry if the content type is opted into public
delivery and the entry is published. Both are off by default. The blueprint turned the first one on
for `post`; `npm run seed` publishes the entries. If the home page is empty, one of those two is
the reason.

**The session lives on the server.** The API returns both tokens in the login response body, so
`lib/session.ts` holds them and hands the browser an http-only cookie of its own. No API token is
readable from JavaScript on the page, the browser never calls the API cross-origin, and the API's
own `Secure` refresh cookie (which cannot work over plain http) is not in the way on localhost.

## Upgrading the stack

The image tags in `compose.yml` are pinned together on purpose. barakoCMS publishes
`X-Api-Contract-Version` and moves it when the HTTP surface breaks a consumer, and the console
declares the range it speaks and refuses to run outside it. Move both tags together and read the
release notes for the contract line.

## What this is not

No design system, no state library, no ORM, no component kit. The palette in `app/globals.css` is
a set of custom properties you can delete. It is a working shape to build on, not a template to
delete your way out of.
